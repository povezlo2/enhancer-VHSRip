# enhancer-VHSRip: нарезка/склейка и генеративное улучшение

> **Статус:** вариант A (этапы 1, 2 в локальной части и 4) сделан. Дальше: этап 3 (SeedVR2 на RunPod).

## Цель

1. Добавить в приложение простой встроенный редактор: нарезать видео на фрагменты по 5–10 с (по сценам или вручную), обработать каждый фрагмент отдельно, склеить результат обратно со звуком оригинала.
2. Подключить генеративное улучшение (SeedVR2), которое дорисовывает мелкие детали: волосы, текстуру кожи, ткань. Модель тяжёлая, поэтому она работает на арендованной видеокарте в облаке. Локальный апскейл (Real-ESRGAN) остаётся быстрым бесплатным вариантом.
3. Итог: до 1080p, без мерцания и без видимых швов на стыках фрагментов.

## Ограничения железа

| | Ноутбук (Vivobook S 15 M5506UA) | Облако (RTX 4090, 24 ГБ) |
|---|---|---|
| GPU | Radeon 780M, без CUDA, память общая с системой | NVIDIA, CUDA |
| ffmpeg: нарезка, склейка, деинтерлейс, шумодав | ✅ быстро | не нужно |
| Real-ESRGAN (ncnn-vulkan) | ✅ работает, медленно | ✅ быстро |
| CodeFormer / GFPGAN (лица) | ✅ через ONNX + DirectML | ✅ |
| SeedVR2 (генеративный апскейл) | ❌ нужна CUDA и 16+ ГБ видеопамяти | ✅ |
| Эксперименты с референсами (ComfyUI + IP-Adapter) | ❌ | ✅ |

## Варианты реализации

### Вариант A — только локально (0 $)
- Нарезка и склейка, предобработка ffmpeg, Real-ESRGAN, CodeFormer для лиц.
- **Плюсы:** бесплатно, работает офлайн, всё приватно.
- **Минусы:** волосы не дорисовываются, только становятся чуть резче.

### Вариант B — локально + RunPod Serverless (рекомендую)
- Приложение само отправляет фрагмент на serverless-эндпоинт с SeedVR2 и забирает результат. Вручную включать и выключать сервер не нужно.
- **Цена:** около $1.10/ч за RTX 4090, но оплачиваются только секунды активной обработки. Простой ничего не стоит.
- **Плюсы:** одна кнопка в приложении, нельзя забыть выключить сервер.
- **Минусы:** нужно один раз собрать Docker-образ. Первый запуск после простоя медленный («холодный старт», модель грузится в память).

### Вариант C — локально + RunPod Pod (вручную)
- Арендуешь под с 4090 на время сессии, приложение отправляет на него задания, потом под останавливаешь.
- **Цена:** около $0.34/ч в Community Cloud, около $0.69/ч в Secure Cloud. Плюс сетевой том для моделей, примерно $0.07 за ГБ в месяц.
- **Плюсы:** дешевле за час, проще отлаживать: есть SSH и Jupyter.
- **Минусы:** если забыть остановить под, деньги продолжат списываться.

### Вариант D — эксперимент с референсами (поверх B или C)
- ComfyUI на том же поде. Ключевые кадры обрабатываются через IP-Adapter с качественными фото-референсами (волосы, лицо), результат сравнивается с чистым SeedVR2.
- **Риск:** покадровая генерация даёт мерцание. Это исследование, а не гарантированная функция.

> **Предложение:** A → C (для отладки) → B (для удобства), D — по желанию в конце.

## Шаги

### Этап 1. Нарезка и склейка (локально, вариант A)
- [x] Автонарезка по сценам: `select='gt(scene,T)',showinfo` на уменьшенной серой копии, три уровня чувствительности. Сцены < 5 с присоединяются к соседним, > 10 с делятся поровну.
- [x] Ручные маркеры на таймлайне в UI (покадровая навигация по H.264-копии исходника), слияние и разделение соседних фрагментов.
- [x] Нарезка точно по кадру. Кадр N — временная позиция N / fps. Поиск идёт с запасом в 1 с, затем фильтр `fps` по меткам времени (`-copyts`), поэтому учитываются и выпавшие кадры VHS-захвата. Промежуточный ffv1 не понадобился: кадры фрагмента идут в PNG, а результат сразу кодируется в итоговый H.264.
- [x] **Нахлёст:** 8 кадров «разогрева» перед фрагментом для временных фильтров (`bwdif`, `hqdn3d`) плюс `contextFrames` от процессора (для SeedVR2) с обеих сторон. После обработки запас отбрасывается. Проверено тестом: без временных фильтров склейка совпадает с цельной обработкой бит в бит, с фильтрами стыки на уровне ≥ 66 дБ PSNR.
- [x] Звук в обработку не идёт: берётся из оригинала один раз, при склейке.
- [x] Склейка: concat demuxer с `-c copy`, без второго перекодирования (все фрагменты закодированы с одинаковыми параметрами и постоянным шагом кадров), плюс оригинальный звук в AAC.
- [x] Предобработка как отдельный шаг: `idet` → `bwdif` → `crop` → `hqdn3d`/`nlmeans` → цвет (была и раньше).

### Этап 2. Абстракция «процессор»
- [x] Общий интерфейс `FrameProcessor` (`electron/processors`): `LocalRealEsrgan`, `LocalFaceRestore` (CodeFormer/GFPGAN). `RunPodSeedVR2` — на этапе 3.
- [x] Очередь фрагментов, прогресс по фрагментам, до 3 попыток на фрагмент, кэш готовых фрагментов по хэшу входа, диапазона, настроек и версий моделей (LRU, 10 ГБ).
- [~] Режим сравнения: кнопка «Превью фрагмента» и существующее сравнение моделей Real-ESRGAN «рядом/шторкой». Сравнение разных процессоров (Real-ESRGAN vs SeedVR2) — вместе с этапом 3.

### Этап 3. Облако: SeedVR2
- [ ] Docker-образ: Python + PyTorch (CUDA) + standalone-скрипт SeedVR2 (работает без ComfyUI) + handler для RunPod.
- [ ] Модель 3B (fp8/GGUF) для старта, 7B — если качества не хватит.
- [ ] Параметры: `batch_size` ≥ 5 (иначе не будет темпоральной согласованности), BlockSwap при нехватке памяти, целевое разрешение до 1080p.
- [ ] Сначала вариант C (под, отладка), потом тот же образ разворачивается как Serverless (вариант B).
- [ ] Передача файлов: загрузка фрагмента в хранилище (S3-совместимое или network volume) → в задачу уходит ссылка → результат скачивается обратно.
- [ ] В настройках приложения: API-ключ RunPod (хранить через `safeStorage` Electron), ID эндпоинта, лимит расходов на сессию.

### Этап 4. Лица (локально)
- [x] CodeFormer (ONNX) с fidelity 0.7 по умолчанию, ползунок «Похожесть» в настройках. GFPGAN остался как альтернатива.
- [x] Включение и выключение лиц для каждого фрагмента. Автоматического определения «крупных планов» пока нет: лица меньше 48 px и так пропускаются.

### Этап 5 (опционально). Референсы
- [ ] Воркфлоу ComfyUI: SeedVR2 → ключевые кадры через IP-Adapter с референсами → оценка мерцания.
- [ ] Решение: оставить как экспериментальную опцию или отказаться.

### Этап 6. Проверка
- [ ] Набор из 5–10 тестовых клипов: крупный план с волосами, движение, темнота, шум.
- [ ] Замер времени и стоимости на клип для каждого процессора, таблица результатов в README.

## Что требуется от тебя

1. **Зарегистрироваться на RunPod** (runpod.io) и пополнить баланс. Для начала хватит ~$10: при оценке выше это сотни клипов. Включить уведомления о низком балансе. Автопополнение лучше не включать.
2. **Создать API-ключ** в настройках RunPod (Settings → API Keys). Ключ хранить только в приложении, в репозиторий не коммитить.
3. **Аккаунт для Docker-образа:** Docker Hub или GitHub Container Registry (GHCR удобнее, у тебя уже есть GitHub). Собирать образ можно через GitHub Actions, локальный Docker не обязателен.
4. **Установить ffmpeg** на ноутбук, если его ещё нет, или решить, что приложение поставляет его с собой (`ffmpeg-static`).
5. **Подготовить 5–10 тестовых клипов** разного типа (см. этап 6).
6. **Принять решения:**
   - вариант: A → C → B (рекомендую) или сразу B;
   - Community или Secure Cloud (для личных видео рекомендую Secure: это проверенные дата-центры);
   - нужен ли этап 5 с референсами.
7. **Помнить об остановке пода** в варианте C. В приложении можно сделать автоостановку через API после очереди.

## Порядок работы

Этап 1 → этап 2 → этап 3 (под) → замер на тестовых клипах → этап 3 (serverless) → этап 4 → этап 5 по желанию.
Этап 1 не зависит от облака, его можно делать уже сейчас, пока идёт регистрация на RunPod.
