# Этап 3. SeedVR2 на RunPod

Подробный план этапа 3 из [PLAN-generative-enhance.md](PLAN-generative-enhance.md). Код пока не пишем: документ фиксирует, что строим, в каком порядке и как проверяем.

## Цель

Добавить третий движок апскейла: **SeedVR2**, генеративную модель восстановления видео от ByteDance Seed. В отличие от Real-ESRGAN она дорисовывает мелкие детали (волосы, кожу, ткань) и учитывает соседние кадры, поэтому меньше мерцает.

Модели нужна CUDA и 16+ ГБ видеопамяти, на ноутбуке (Radeon 780M) она не запустится. Поэтому обработка идёт на арендованной RTX 4090 в RunPod. Для пользователя это выглядит как ещё один вариант в настройках: «SeedVR2 (облако)».

**Результат этапа:** фрагмент из редактора уходит в облако, возвращается улучшенным до 1080p и склеивается с остальными так же бесшовно, как сейчас. Стоимость видна до запуска, а сервер нельзя забыть выключить.

## Что уже готово (вариант A)

Этап 3 опирается на то, что сделано в варианте A:

- **Фрагменты по 5–10 с** с покадрово точной нарезкой и склейкой без перекодирования (`electron/fragment.ts`, `electron/pipeline.ts`).
- **Интерфейс `FrameProcessor`** (`electron/processors/types.ts`). SeedVR2 станет ещё одной его реализацией.
- **`contextFrames`:** процессор может попросить соседние кадры с каждой стороны. Конвейер уже декодирует их и отбрасывает после обработки. Для SeedVR2 это нахлёст, без которого на стыках будут швы.
- **Кэш фрагментов** по хэшу входа и настроек. Оплаченная облачная обработка не потеряется при отмене, сбое или повторном запуске.
- **До 3 попыток** на фрагмент.

## Как это будет работать

```
Ноутбук (Electron)                                     RunPod (RTX 4090)
─────────────────                                      ─────────────────
ffmpeg: деинтерлейс, crop, шумодав
  → кадры фрагмента + запас соседних
  → сжатие без потерь (ffv1 / x264 qp 0)
  → загрузка в хранилище ─────────────────────────────> воркер скачивает фрагмент
                                                         SeedVR2 (inference_cli.py)
                                                         → 1080p, x264 crf ~10
  скачивание результата <───────────────────────────── загрузка результата
  → кадры PNG → (лица CodeFormer, по желанию)
  → резкость, кодирование фрагмента → склейка
```

Важно:

- **Предобработка остаётся локальной:** деинтерлейс и обрезка обязательны, шумодав слабее обычного. SeedVR2 сама справляется с шумом, а сильный `hqdn3d` стирает детали, за которыми она «цепляется».
- **SeedVR2 заменяет Real-ESRGAN, а не дополняет его.** Цепочка: `RunPodSeedVR2 → LocalFaceRestore (опционально)`.
- **По сети ходит сжатое видео, а не PNG.** 10 с в 576p в PNG весят около 150 МБ, в ffv1 около 30–60 МБ. Результат 1080p в x264 crf ~10 весит десятки МБ.
- **Файлы не помещаются в запрос к API.** У RunPod лимит 10 МБ на `/run` и 20 МБ на `/runsync`, поэтому файлы идут через хранилище по временным ссылкам, а в задание передаются только ссылки.

## Два режима: Pod и Serverless

| | Pod (вариант C) | Serverless (вариант B) |
|---|---|---|
| Как работает | Арендуем машину на сессию, приложение шлёт ей фрагменты по HTTPS | RunPod сам поднимает воркер под задачу и гасит после |
| Цена RTX 4090 | ~$0.34/ч Community, ~$0.69/ч Secure, пока под запущен | ~$1.10/ч, только секунды активной работы |
| Холодный старт | Один раз при запуске пода (загрузка образа и модели, минуты) | Каждый раз после простоя (десятки секунд или минуты) |
| Отладка | SSH, Jupyter, логи вживую | Только логи задач |
| Риск перерасхода | Забыть остановить под | Почти нет (min workers = 0) |
| Передача файлов | Напрямую на под: HTTP-сервер в образе + токен | Через хранилище (S3/R2), временные ссылки |

**Порядок:** сначала Pod (отладка, подбор параметров, замеры), потом тот же образ разворачивается как Serverless. Код обработки в воркере общий, различается только «обвязка» (HTTP-сервер для пода, `runpod.serverless.start` для serverless).

## SeedVR2: что используем

- **Реализация:** standalone CLI из [numz/ComfyUI-SeedVR2_VideoUpscaler](https://github.com/numz/ComfyUI-SeedVR2_VideoUpscaler) (`inference_cli.py`, лицензия Apache 2.0). Работает без ComfyUI, умеет FP8 и GGUF, BlockSwap, тайлинг VAE, перекрытие батчей. Закрепляем конкретный коммит, потому что параметры CLI менялись между версиями.
- **Модель для старта:** `seedvr2_ema_3b_fp8_e4m3fn.safetensors` (3B, FP8). Если качества не хватит, пробуем 7B: `seedvr2_ema_7b_fp8_e4m3fn_mixed_block35_fp16.safetensors`.
- **Лицензия весов:** проверить на странице модели ByteDance-Seed на Hugging Face до первого публичного релиза. Ожидается Apache 2.0.

Ключевые параметры CLI (сверено с README репозитория, перед реализацией перепроверить `--help` закреплённой версии):

| Параметр | Значение | Зачем |
|---|---|---|
| `--resolution` | короткая сторона цели, 1080 или меньше | Итоговое разрешение. 576p → 1080p примерно ×1.9 |
| `--max_resolution` | 1920 | Не превышать Full HD по длинной стороне |
| `--batch_size` | 4n+1: 5, 9, 13, 21, 33… | Кадров в одном проходе. Больше значит лучше согласованность во времени, но нужно больше VRAM. **Обязательно 4n+1** |
| `--uniform_batch_size` | вкл. | Последний батч дополняется до полного, качество ровное по всему фрагменту |
| `--temporal_overlap` | 3–4 | Перекрытие батчей внутри фрагмента |
| `--prepend_frames` | 4 | Убирает артефакты в начале (если контекста мало) |
| `--color_correction` | `lab` | Сохраняет исходные цвета |
| `--seed` | фиксированный | Повторный запуск даёт тот же результат, кэш честный |
| `--blocks_to_swap`, `--vae_*_tiled` | только при нехватке памяти | Медленнее |
| `--output_format` | `png` или mp4 через `--video_backend ffmpeg` | Выбрать при замерах |

**`contextFrames` процессора:** 8 кадров с каждой стороны (подобрать при замерах, но не меньше `temporal_overlap`). Конвейер уже умеет их отдавать и отбрасывать.

## Шаги

### 3.0. Подготовка (делаешь ты, ~30 минут)

- [ ] Аккаунт RunPod, пополнение на $10, уведомление о низком балансе. Автопополнение не включать.
- [ ] API-ключ RunPod (Settings → API Keys). Ключ с правами только на нужное: pods, serverless.
- [ ] Хранилище для режима Serverless. Рекомендую **Cloudflare R2**: 10 ГБ бесплатно, нет платы за скачивание, S3-совместимый API. Нужны bucket и ключ доступа к нему. Альтернатива: S3 API сетевого тома RunPod, но он есть не во всех дата-центрах.
- [ ] Реестр образов: **GHCR** (GitHub Container Registry), сборка через GitHub Actions. Локальный Docker не нужен.
- [ ] Решения: Secure или Community Cloud (для личного видео рекомендую Secure); модели в образе или на сетевом томе (см. «Открытые вопросы»).

### 3.1. Воркер (Python)

Папка `cloud/seedvr2-worker/` в этом репозитории.

- [ ] `core.py`: одна функция `process(job) → result`, общая для обоих режимов:
  1. скачать фрагмент по ссылке и проверить размер и хэш;
  2. запустить `inference_cli.py` с параметрами из задания (белый список параметров, никаких произвольных аргументов);
  3. проверить число кадров на выходе (должно совпасть со входом);
  4. загрузить результат и вернуть метаданные: кадры, время, пиковая VRAM, версия модели.
- [ ] Прогресс: парсить вывод CLI и отдавать проценты (`runpod.serverless.progress_update` в serverless, эндпоинт статуса в поде).
- [ ] Отмена: убивать процесс CLI, чистить временные файлы.
- [ ] Модели скачиваются один раз в кэш (`/runpod-volume` или каталог образа) и проверяются по размеру и хэшу.
- [ ] `server.py` (режим Pod): небольшой HTTP-сервер (FastAPI): `POST /jobs` (загрузка фрагмента), `GET /jobs/{id}` (статус и прогресс), `GET /jobs/{id}/result`, `DELETE /jobs/{id}`, `GET /health`. Авторизация по токену в заголовке: токен генерирует приложение и передаёт поду в переменной окружения при создании.
- [ ] `handler.py` (режим Serverless): `runpod.serverless.start({"handler": ...})`, вход и выход через временные ссылки на хранилище.
- [ ] **Самоостановка пода:** если N минут (по умолчанию 10) нет заданий, под останавливает сам себя через API RunPod. Это страховка на случай, если приложение закрыто или упало.
- [ ] Тесты без GPU: заглушка вместо `inference_cli.py` (например, ffmpeg-апскейл), проверка протокола, отмены и подсчёта кадров. Запуск в CI.

### 3.2. Docker-образ

- [ ] База: официальный образ RunPod с PyTorch и CUDA 12.x (версию PyTorch подобрать под требования закреплённого коммита SeedVR2).
- [ ] Внутри: ffmpeg, закреплённый коммит SeedVR2 CLI, зависимости, `core.py`, `server.py`, `handler.py`. Один образ, режим выбирается переменной окружения.
- [ ] GitHub Actions: сборка и публикация в `ghcr.io/povezlo2/enhancer-seedvr2:<версия>` по тегу. Модели в образ не кладём: у раннеров GitHub около 14 ГБ свободного диска, а образ тогда весил бы 15+ ГБ.
- [ ] Проверка на поде вручную: `inference_cli.py --help`, один тестовый фрагмент, замер VRAM.

### 3.3. Режим Pod в приложении (вариант C)

- [ ] **`RunPodSeedVR2` реализует `FrameProcessor`:** `stage: 'upscale'`, `contextFrames: 8`, сигнатура для кэша (модель, все параметры CLI, версия образа). На входе каталог PNG: сжимает его в ffv1, отправляет, ждёт, скачивает, раскладывает обратно в PNG.
- [ ] **Управление подом через API RunPod:** создать (образ, GPU, Secure/Community, том, токен), дождаться `/health`, остановить, удалить. Под создаётся при первом облачном фрагменте в очереди.
- [ ] **Автоостановка:** после очереди (и при отмене или закрытии приложения) под останавливается. Плюс самоостановка в воркере на случай, если приложение упало.
- [ ] **Учёт денег:** время работы пода × цена за час, показывается в UI живьём. **Лимит на сессию** (например, $2): при достижении очередь ставится на паузу, под останавливается, приложение спрашивает, продолжать ли.
- [ ] **Сеть:** таймауты, повтор загрузки, докачка; при обрыве задание на поде не теряется (статус запрашивается по id).
- [ ] **Отмена фрагмента:** `DELETE /jobs/{id}`, под продолжает работать для следующих.

- [ ] Проверить швы на стыках фрагментов: склейка фрагментами против одного длинного прохода. Метрика как в варианте A (PSNR на стыках) плюс визуальная проверка мерцания.
- [ ] Таблица в README: секунды обработки на 1 с видео, пиковая VRAM, цена за минуту видео для каждого варианта.

### 3.5. Режим Serverless (вариант B)

- [ ] Эндпоинт RunPod на том же образе: GPU 4090 (запасной вариант: другая карта с 24 ГБ), **min workers = 0**, max workers = 1–2, idle timeout ~5 с, таймаут выполнения задачи, FlashBoot.
- [ ] Модели на сетевом томе в том же дата-центре, что и эндпоинт, иначе каждый холодный старт скачивает гигабайты.
- [ ] Хранилище: приложение загружает фрагмент в R2 по временной ссылке, передаёт в задание ссылки на чтение входа и запись результата (срок жизни ~1 ч), после скачивания удаляет оба объекта.
- [ ] Клиент: `POST /v2/{endpoint}/run` → id, опрос `/status/{id}` с прогрессом, `/cancel/{id}` при отмене. Результаты асинхронных задач RunPod хранит 30 минут: забирать сразу.
- [ ] Холодный старт показывается в UI как отдельная стадия («запуск сервера»), чтобы долгое ожидание первого фрагмента не выглядело как зависание.
- [ ] Учёт денег: по `executionTime` из ответа × цена за секунду, тот же лимит на сессию.

### 3.6. Интерфейс

- [ ] **Настройки → «Облако»:** режим (Pod / Serverless), API-ключ RunPod, ID эндпоинта, доступ к R2, Secure/Community, лимит расходов на сессию, кнопка «Проверить подключение». Секреты хранятся через `safeStorage` Electron (шифрование средствами ОС), в renderer не передаются и в логи не пишутся.
- [ ] **Движок «SeedVR2 (облако)»** рядом с «Нейросеть» и «Быстро». Подсказка про стоимость и приватность: видео уходит на сторонний сервер.
- [ ] **Оценка до запуска:** «~N мин, ~$X» на основе замеров, с подтверждением при запуске очереди.
- [ ] **Стадии прогресса:** запуск сервера → загрузка → в очереди → обработка (%) → скачивание. Расход денег в шапке рядом с кэшем.
- [ ] **Движок на фрагмент:** в редакторе фрагментов можно выбрать SeedVR2 только для важных сцен (крупные планы), остальное обработать локально. Это главный способ экономить.
- [ ] Превью фрагмента с SeedVR2 и сравнение с Real-ESRGAN «шторкой».

### 3.7. Надёжность и безопасность

- [ ] **Кэш:** ключ включает модель, параметры, сид и версию образа. Оплаченный фрагмент не пересчитывается.
- [ ] **Повторы:** сетевые сбои повторяются, ошибки модели (OOM) повторяются с `blocks_to_swap` или меньшим `batch_size`, при окончательной ошибке нужна понятная причина.
- [ ] **Приватность:** только HTTPS, временные ссылки короткие, файлы на поде и в хранилище удаляются сразу после скачивания. Сетевой том хранит только модели, без видео.
- [ ] **Деньги:** на каждом пути выхода (готово, отмена, ошибка, закрытие окна, падение приложения) под останавливается. Это покрывают тесты на заглушке API RunPod.

## Критерии готовности

1. Фрагмент 576p → 1080p через SeedVR2 в обоих режимах, результат склеивается с соседними без видимых швов и мерцания на стыках.
2. Число кадров и синхронизация звука как в варианте A (тот же интеграционный тест, но с заглушкой облака).
3. Под гарантированно останавливается после очереди, при отмене и при закрытии приложения. Самоостановка срабатывает, если приложение упало.
4. Лимит расходов работает: при его достижении обработка ставится на паузу.
5. Ключи хранятся зашифрованными, в логах и в renderer их нет.
6. В README есть таблица времени и стоимости по тестовым клипам.

## Риски

- **Мерцание и «чужие» детали.** Генеративная модель может дорисовать не то. Нужно сравнение с Real-ESRGAN на каждом типе сцен, а по умолчанию SeedVR2 включать только для выбранных фрагментов.
- **Нехватка VRAM** на 7B или больших `batch_size`: BlockSwap и тайлинг спасают, но замедляют. Определится замерами.
- **Холодный старт serverless** может быть минуты, если модели не на томе в том же дата-центре.
- **Изменения CLI SeedVR2:** параметры уже переименовывались между версиями. Закрепляем коммит, обновляем осознанно.
- **Доступность 4090** в Secure Cloud конкретного дата-центра: нужен запасной тип GPU.
- **Сеть пользователя:** загрузка 30–60 МБ на фрагмент при медленном интернете может занимать больше, чем сама обработка. Если так, перейти на x264 почти без потерь (crf ~8) вместо ffv1.

## Открытые вопросы (решить до начала)

1. **Модели в образе или на сетевом томе?** Том: образ меньше, сборка в GitHub Actions проще, но том привязан к дата-центру и стоит денег в простое. Образ: быстрее холодный старт везде, но 15+ ГБ и сборка не на бесплатных раннерах. Рекомендую том.
2. **Хранилище для serverless:** Cloudflare R2 (рекомендую) или S3 API тома RunPod?
3. **Secure или Community Cloud?** Для личного видео рекомендую Secure.
